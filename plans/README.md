## Findings considered and rejected

- A stalled `wm subscribe` client blocking all subscribers: `Controller.swift:776-781` drops a subscriber after one failed write, and the send timeout is 5 s, so the damage is one delay. Not worth a plan.
- The full Lua standard library in the config (`os.execute`, `io`): by design, it is the user's own config file.
- The Unix socket: mode 0600 in a per-user temp directory, frames capped at 1 MiB, 5 s timeouts. Adequate.
- README links to the docs site: all of them resolve.
- Adding a formatter or linter: low value before CI exists; revisit after 001.
- Timer lifecycle smell (many `Timer` and `asyncAfter` uses) and a possible stuck drag after an event-tap timeout (`MouseDrag.swift`): LOW confidence, no evidence of a real leak. The opening-hold refreshes already guard on `openingHold[id]`.
- `--window` ignored by `focus column` / `focus stack` (`Commands.swift:208-226`): the intended semantics are unclear and the impact is small.
- Docs dependency pins and the missing `packageManager` field: low confidence, version ages were not checked.

## Direction (options for the maintainer, not plans)

1. `wm help --json`: the command table as JSON, extending `wm skills`, so agents and scripts validate calls instead of parsing prose (size M).
2. A `wm mcp` server over the existing socket, with the URL allow-list rules applied to agent callers (size L, start with a design spike).
3. A notarized release built on tag, GitHub Releases and a Homebrew cask (size M-L); pairs with 001 and 004.
4. Generate the `cli.md` table and the Lua reference from code, and fail CI on drift (size M); this would replace the textual check in plan 005.
